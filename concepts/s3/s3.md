## Amazon S3
short explanation comes here

### Features
#### general
- use cases:
    - backup and storage
    - disaster recovery
    - archive
    - hybri cloud storage
    - application hosting
    - media hosting
    - data lakes & big data analytics
    - software delivery
    - static website

#### S3 Buckets
- in S3, users store "objects(=files)" in "bucket(directories)"
- buckets must have a **globally unique name** across all regions all accounts
- buckets are defined at the region level
- s3 looks like a global service but buckets are created in a region
- naming conventions
    - no uppercase, no underscore
    - 3-63 chars long
    - shouldn't be an IP address
    - must start with lowercase letter or number
    - have banned prefix/suffix like "xn--", "-s3alias"

#### S3 Objects
- objects(=files) have a key
- the key is the full path like
    - s3://<yourBucketName>/your_file_name.txt
    - s3://<yourBucketName>/dir1/sub_dir2/your_file_name.txt
- the key is composed of **prefix** + *object name*
    - s3://<yourBucketName>/**your_dir1/your_sub_dir2/***your_file_name.txt*
- there's no concept of "directories" within buckets (although the UI will trick you to think  otherwise)
- just kesy with very long names that contain slashes ("/")
- **summarised**:
    - Each object is identified by a key, which looks like a full file path (e.g., bucket/dir1/file.txt).
    - The key is made of a prefix (like folders) plus the object name (the file).
    - S3 doesn't have real folders; the slashes in keys just make it look like folders in the UI.
    - So, it's really just one flat list of keys with long names containing slashes.
    - Analogy: Imagine a bookshelf where all books are just stacked flat but have labels with slashes (SciFi/Space/Book1) to simulate shelves.
- object values are the content for the key:
    - each object can be up-to 5TB size
    - if uploading more than 5GB, then it must be "multi-part upload"
- objects have metadata which are lists of text keys / value pairs or system/user metadata
- tags (unicode key / value pair - up to 10) - useful for security / lifecycle
- version id (if versioning is enabled)
